# Build plan

Ordered work with a definition of done per item. Nothing below item 0 starts before the documents above exist, per the brief.

## Phase 0: documents (complete before code)

- [x] `docs/PRD.md`, scope and acceptance criteria
- [x] `docs/RESEARCH.md`, 14-challenge screen and the decision
- [x] `docs/SCIENCE.md`, frames, equations, metrics, accuracy budget
- [x] `docs/DATA-SOURCES.md`, every source, licence, SI disclosure
- [x] `docs/ARCHITECTURE.md`, stack, modules, budgets, hosting, security
- [x] `DESIGN.md`, locked direction and tokens
- [x] `docs/UX-SPEC.md`, routes, states, keyboard, copy, responsive
- [x] `docs/BUILD-PLAN.md`, this file

Definition of done for phase 0: an engineer could build the product from these files without asking a question. Cross-checked: every screen in the UX spec has a route, every route has data, every data point has a formula in the science note, every formula has a tolerance.

## Phase 1: engine and truth

1. Commit JPL Horizons snapshots to `validation/` (13 epochs of sub-points, two topocentric series). **DoD**: files parse, epochs span 2026 to 2028.
2. `engine/time.ts`, `engine/ephemeris.ts`, `engine/lunarFrame.ts`, `engine/geometry.ts`, `engine/site.ts`.
   **DoD**: `node --experimental-strip-types scripts/validate.ts` prints a residual table inside the acceptance thresholds in `SCIENCE.md` section 8. No UI work until this passes.
3. `engine/planner.ts`: sampling, runs, summaries, score, CSV. **DoD**: unit tests for run detection across a wrap-around boundary and for an all-dark window.
4. `engine/sites.ts`: eight catalogue entries, each with coordinates and a published source. **DoD**: every coordinate matches its paper to the printed precision.

## Phase 2: shell and system

5. Tokens, base CSS, fonts, shell, rail, footer status line. **DoD**: both themes pass contrast; rail has a focus order that matches visual order.
6. Router, URL state hook, document meta per route, 404. **DoD**: every route round-trips its parameters; a cold load of a deep link renders the same view as a navigation.

## Phase 3: screens

7. Horizon screen with canvas panorama, readouts, sector editor, profile import, 30 day strip. **DoD**: scrubbing never re-computes the ephemeris twice for one sample; occluded markers print the word `occluded`.
8. Compare screen with sortable table and CSV export. **DoD**: sorting is stable, the CSV matches the table row for row, and a screen reader reads the header cell with the sort state.
9. Dates screen with the scan and a jump into the horizon view. **DoD**: a 180 day scan completes under 400 ms.
10. Sites and Model screens. **DoD**: the Model accuracy table is rendered from `validation/residuals.json`, produced by the validator, not hand typed.

## Phase 4: evidence and submission artifacts

11. `scripts/figures.ts` renders the panorama and the comparison table to SVG, then `sharp` to PNG at 2x. **DoD**: figures are generated by the same engine functions the app calls, never drawn by hand.
12. `docs/SUBMISSION.md`, `docs/VIDEO.md` (30 s script and shot list), `docs/DECK.md` (7 slides), README. **DoD**: submission text answers all five judging criteria with evidence, not adjectives.
13. Demo capture path for the 30 s video: exact screen sequence, timings, and what the narration says at each beat.

## Phase 5: audit and release

14. `npm run verify`: typecheck, tests, validation thresholds, build, link check. **DoD**: green.
15. Anti-slop audit pass against the provided specification, recorded in `docs/COVERAGE-MATRIX.md` with one line of evidence per item. **DoD**: every item either applied or listed as a recorded exception with a reason.
16. Final commit on `arena/21cdfec2-space-apps`. **DoD**: working tree clean, no secrets, no `node_modules`, no build output.

## Cut list, in order, if time runs short

1. The 30 day strip on the horizon screen (the panorama still answers the question).
2. The dates screen (the compare screen covers "which site", the horizon view covers "which moment").
3. The command palette (the rail still reaches every route).
4. CSV export of the hourly series (the comparison export stays).

Never cut: validation, the model page, the keyboard reachability of the primary controls, the SI disclosure, the submission documents.
